# เอกสารข้อกำหนดความต้องการเชิงฟังก์ชัน (FRS)

**ระบบ Livora (Daily Life Companion)** · ขอบเขต V1 · ผู้จัดทำ: Chayaphat

## 1. บทนำ

### 1.1 วัตถุประสงค์

เอกสารนี้กำหนดความต้องการเชิงฟังก์ชัน (Functional Requirements Specification) ของระบบ Livora (Daily Life Companion) เวอร์ชัน V1 เพื่อใช้เป็นข้อตกลงร่วมกันว่าระบบต้องทำอะไร ผู้ใช้ใช้งานอย่างไร และมีกฎทางธุรกิจอะไรบ้าง ก่อนนำไปออกแบบฐานข้อมูล API และหน้าจอ

### 1.2 ขอบเขตของระบบ (V1)

- สมัครสมาชิก เข้าสู่ระบบ และจัดการบัญชีผู้ใช้
- วางแผนงาน (Task) รวมงานที่ทำซ้ำ และประวัติงาน
- ปฏิทินรายเดือนพร้อมวันหยุดไทย
- นิสัย (Habit) การ check-in และ streak
- XP และ Level
- เป้าหมาย (Goal) ที่วัดผลเป็นตัวเลข
- กลุ่ม (Group) งานกลุ่ม และอันดับในกลุ่ม
- Dashboard หน้าหลักของวัน
- การแจ้งเตือน (Reminder)
- ดวงรายวัน (ไพ่ยิปซี) และแคลอรี่

### 1.3 สิ่งที่ไม่อยู่ในขอบเขต V1

- Focus timer
- Global ranking / ranking รายสัปดาห์
- ยืนยันอีเมล และลืมรหัสผ่านผ่านอีเมล
- อัปโหลดรูปโปรไฟล์ และ OAuth
- งานซ้ำแบบรายเดือน / กำหนดเอง
- บันทึกอาหาร และเป้าหมายลด/เพิ่มน้ำหนัก
- เชื่อมต่อ Google Calendar
- แอปมือถือ (V1 เป็น Responsive Web)

### 1.4 คำศัพท์

| คำศัพท์ | ความหมาย |
| --- | --- |
| Task | งานที่ผู้ใช้สร้างขึ้น มีหรือไม่มีวันที่ก็ได้ |
| Recurring task | งานที่ทำซ้ำตามรอบ เช่น ทุกวัน หรือทุกวันจันทร์/พุธ |
| Occurrence | งานที่ทำซ้ำในวันใดวันหนึ่ง |
| Habit | สิ่งที่ผู้ใช้ต้องการทำสม่ำเสมอ มี streak |
| Check-in | การบันทึกว่าวันนี้ทำ habit แล้ว |
| Streak | จำนวนวันที่ทำต่อเนื่องตามวันที่กำหนด |
| XP | คะแนนประสบการณ์ที่ได้จากการทำกิจกรรม |
| Group task | งานที่สร้างในกลุ่ม มีผู้รับผิดชอบ 1 คนขึ้นไป |
| Timezone | เขตเวลาของผู้ใช้ ใช้กำหนดขอบเขตของ "วัน" |

## 2. ภาพรวมระบบ

### 2.1 แนวคิดหลัก

**วางแผนวัน → ทำกิจกรรม → สร้างนิสัย → ได้ XP → รักษา streak → เดินหน้าสู่เป้าหมาย → ติดตามความคืบหน้ากับกลุ่ม**

### 2.2 สถาปัตยกรรม

- Browser → Next.js (Frontend) → REST API /api → NestJS (Backend) → PostgreSQL บน Supabase
- Frontend ทำหน้าที่แสดงผล รับข้อมูลจากผู้ใช้ และเรียก API เท่านั้น
- Backend รับผิดชอบกฎทางธุรกิจ การตรวจสอบข้อมูล สิทธิ์การเข้าถึง และการคำนวณ XP / streak / อันดับ / ความคืบหน้าเป้าหมาย
- ระบบยืนยันตัวตนทำเองที่ API (ไม่ใช้ Supabase Auth)

### 2.3 ผู้ใช้งานระบบ

| ผู้ใช้ | คำอธิบาย | สิทธิ์ |
| --- | --- | --- |
| Guest | ผู้ที่ยังไม่เข้าสู่ระบบ | ดูหน้า landing ได้เท่านั้น |
| User | ผู้ใช้ทั่วไป (role USER) | ใช้งานทุกฟีเจอร์กับข้อมูลของตนเอง |
| Admin | ผู้ดูแลระบบ (role ADMIN) | ใช้งานเหมือน User และจัดการผู้ใช้ / วันหยุด |

## 3. หลักการออกแบบ

| หลักการ | รายละเอียด |
| --- | --- |
| Daily-first | ระบบต้องตอบคำถาม "วันนี้ต้องทำอะไร และคืบหน้าแค่ไหน" หน้า Today และ Dashboard เป็นหน้าหลัก |
| ฟีเจอร์เชื่อมกัน | Goal → Habit/Task → ทำเสร็จ → XP → Level / อันดับกลุ่ม ไม่ใช่แอปย่อยที่แยกขาดจากกัน |
| ใช้งานก่อน เกมทีหลัง | XP ช่วยให้ทำสม่ำเสมอ แต่ไม่ให้ XP กับทุกการกระทำ และต้องกันการโกง XP |
| V1 เท่าที่จำเป็น | ไม่ทำฟีเจอร์นอกขอบเขต V1 จนกว่าจะได้รับอนุมัติ |
| เชื่อข้อมูลจาก Backend | ไม่เชื่อ user_id ที่ส่งมาจาก client ระบบระบุตัวผู้ใช้จาก token ที่ตรวจสอบแล้วเสมอ |

## 4. ความต้องการเชิงฟังก์ชัน

### 4.1 การยืนยันตัวตนและบัญชีผู้ใช้

| รหัส | ความต้องการ |
| --- | --- |
| FR-A1 | สมัครสมาชิกด้วย email, username, password, เพศ และ timezone |
| FR-A2 | เข้าสู่ระบบด้วย email และ password |
| FR-A3 | ออกจากระบบ |
| FR-A4 | ดู/แก้ไขโปรไฟล์: username, เพศ, timezone, ภาษา UI (แก้ email ไม่ได้) |
| FR-A5 | เปลี่ยนรหัสผ่าน โดยต้องใส่รหัสผ่านเดิม |
| FR-A6 | ลบบัญชีตนเอง โดยต้องใส่รหัสผ่านยืนยัน |
| FR-A7 | Admin: ดูรายชื่อผู้ใช้ เปลี่ยน role ระงับ/ยกเลิกระงับ และลบผู้ใช้ |
| FR-A8 | Guest เข้าถึงได้เฉพาะหน้า landing |

#### ขั้นตอนการใช้งาน

**สมัครสมาชิก**

1. กรอก email, username, password และเลือกเพศ
2. เลือกประเทศ ถ้าประเทศนั้นมีหลาย timezone ให้เลือกเมือง (ค่าเริ่มต้น: ประเทศไทย)
3. ระบบตรวจสอบข้อมูล
4. ระบบสร้างบัญชี role USER และเข้าสู่ระบบให้อัตโนมัติ
5. เข้าสู่หน้า Dashboard

**เข้าสู่ระบบ**

1. กรอก email และ password
2. ถ้าถูกต้อง ระบบสร้าง session อายุ 7 วัน และไปที่ Dashboard
3. ถ้าไม่ถูกต้อง แสดง "email หรือรหัสผ่านไม่ถูกต้อง" โดยไม่บอกว่าผิดช่องใด

**Session หมดอายุ**

1. ระบบพาไปหน้า login
2. เมื่อเข้าสู่ระบบอีกครั้ง พากลับไปหน้าเดิม

**ลบบัญชี**

1. กดลบบัญชี
2. ใส่รหัสผ่านและยืนยัน
3. ระบบลบบัญชีแบบ soft delete และออกจากระบบทันที

#### กฎทางธุรกิจ

- email และ username ต้องไม่ซ้ำกับบัญชีที่ยังไม่ถูกลบ
- รหัสผ่านอย่างน้อย 8 ตัวอักษร ต้องมีทั้งตัวอักษรและตัวเลข และเก็บเป็น hash เท่านั้น
- session มีอายุคงที่ 7 วัน (ไม่ต่ออายุอัตโนมัติ) และสิ้นสุดก่อนกำหนดเมื่อ logout
- เปลี่ยน role ได้โดย Admin เท่านั้น
- Admin ลด role หรือลบตัวเองไม่ได้ เพื่อให้ระบบมี Admin อย่างน้อย 1 คนเสมอ
- ผู้ใช้ที่ถูกระงับเข้าสู่ระบบไม่ได้ และ session ที่ค้างอยู่ใช้ไม่ได้ทันที
- บัญชีที่ถูกลบหรือถูกระงับไม่แสดงในกลุ่มและอันดับ
- ค่าเริ่มต้น: ภาษา UI อังกฤษ (สลับเป็นไทยได้), timezone Asia/Bangkok
- Admin คนแรกสร้างผ่าน seed
- รูปโปรไฟล์ใน V1 ใช้ตัวอักษรแรกของ username

### 4.2 การวางแผนงาน (Task / Planner)

มี 3 หน้า: Today (งานวันนี้), Upcoming (7 วันข้างหน้า) และ All (งานทั้งหมด รวมงานที่ไม่มีวันที่)

| รหัส | ความต้องการ |
| --- | --- |
| FR-T1 | สร้างงาน: ชื่อ (บังคับ), รายละเอียด, วันที่, เวลาเริ่ม-จบ, priority, category และการทำซ้ำ |
| FR-T2 | ดูรายละเอียด แก้ไข และลบงาน (ลบจริง ต้องยืนยันก่อน) |
| FR-T3 | เปลี่ยนสถานะเป็น DONE หรือ CANCELLED และย้อนกลับเป็นยังไม่เสร็จได้ ผู้ใช้ตั้ง IN_PROGRESS เองได้ (ไม่บังคับ) |
| FR-T4 | ข้าม (SKIPPED) ได้เฉพาะวันหนึ่งของงานที่ทำซ้ำ |
| FR-T5 | ลากวาง: หน้า Today จัดลำดับในวัน, หน้า All ลากไปวันอื่นเพื่อย้ายวันที่ |
| FR-T6 | จัดการ category ของตนเอง: สร้าง เปลี่ยนชื่อ เปลี่ยนสี ลบ |
| FR-T7 | กรองงานตาม category, priority และสถานะ |
| FR-T8 | ประวัติงาน (History): งานที่จบแล้ว (DONE / CANCELLED / SKIPPED) หน้า Today แสดงของวันนี้ หน้า All เลือกช่วง 1 / 7 / 30 วัน / ทั้งหมด เรียงจากล่าสุด และย้อนสถานะจาก History ได้ |

#### ขั้นตอนการใช้งาน

**สร้างงาน**

1. กดเพิ่มงาน
2. กรอกชื่องาน (ช่องอื่นไม่บังคับ)
3. บันทึก
4. งานแสดงในหน้าที่ตรงกับวันที่ (ไม่มีวันที่ แสดงเฉพาะหน้า All)

**ทำงานเสร็จ**

1. กด checkbox งานเปลี่ยนเป็น DONE และได้ XP
2. กดซ้ำเพื่อย้อนกลับ ระบบเตือนว่า XP จะถูกหักก่อนยืนยัน

**งานที่ทำซ้ำ**

1. กดเสร็จ / ข้าม / ยกเลิก มีผลเฉพาะวันนั้น
2. แก้ไขงานที่ทำซ้ำ มีผลตั้งแต่วันนี้เป็นต้นไป วันที่ผ่านมาแล้วไม่เปลี่ยน

#### กฎทางธุรกิจ

- สถานะ: TODO (ค่าเริ่มต้น), IN_PROGRESS, DONE, CANCELLED, SKIPPED (เฉพาะงานที่ทำซ้ำ รายวัน)
- ไม่ใส่เวลา = งานทั้งวัน ถ้าใส่เวลาต้องมีทั้งเวลาเริ่มและจบ และเวลาจบต้องหลังเวลาเริ่ม
- งานที่ทำซ้ำต้องมีวันที่เริ่ม
- การทำซ้ำใน V1: ไม่ซ้ำ, ทุกวัน, รายสัปดาห์ (เลือกได้หลายวัน เช่น จ./พ./ศ.)
- วันสิ้นสุดการทำซ้ำไม่บังคับ ถ้าไม่ใส่จะซ้ำไปเรื่อยๆ
- งานที่เลยกำหนดแต่ยังไม่เสร็จแสดงป้าย "เลยกำหนด" โดยสถานะไม่เปลี่ยนเอง
- ลบ category แล้วงานในนั้นยังอยู่ แค่ไม่มี category
- priority มี LOW / MEDIUM / HIGH ค่าเริ่มต้น MEDIUM
- ไม่เก็บชื่อวันแยก ให้คำนวณจากวันที่
- ผู้ใช้เห็นเฉพาะงานของตนเอง (งานกลุ่มดูหัวข้อกลุ่ม)

### 4.3 ปฏิทิน (Calendar)

หน้าแยกต่างหาก ระบบวางงานและ habit ลงในวันให้อัตโนมัติ ผู้ใช้ไม่ต้องกรอกข้อมูลปฏิทินเอง

| รหัส | ความต้องการ |
| --- | --- |
| FR-C1 | วางงานและ habit ลงวันในปฏิทินอัตโนมัติ (งานที่ทำซ้ำแสดงทุกวันที่ซ้ำ habit แสดงในวันที่กำหนด) |
| FR-C2 | มุมมองรายเดือน เลื่อนไปเดือนอื่นได้ และมีปุ่มกลับมาวันนี้ |
| FR-C3 | กดวันเพื่อดูรายการของวันนั้น เพิ่มงานลงวันนั้น และลบงาน |
| FR-C4 | ลากงานไปวันอื่นเพื่อย้ายวันที่ |
| FR-C5 | แสดงวันหยุดราชการและเทศกาลไทย (ตัวเลขสีแดง ชี้แล้วเห็นชื่อวันหยุด) |
| FR-C6 | Admin เพิ่ม แก้ไข และลบวันหยุด |

#### กฎทางธุรกิจ

- ช่องหนึ่งวันแสดงประมาณ 3 รายการ เกินจากนั้นแสดง "+N more"
- รายการที่จบแล้วแสดงแบบจางและขีดฆ่า
- สัปดาห์เริ่มวันอาทิตย์ตามปฏิทินไทย
- UI ภาษาไทยแสดงปี พ.ศ. ภาษาอังกฤษแสดงปี ค.ศ.
- คำนวณวันตาม timezone ของผู้ใช้
- งานที่ไม่มีวันที่ไม่แสดงในปฏิทิน
- ย้ายหรือลบงานที่ทำซ้ำจากปฏิทิน ต้องถามก่อนว่า "เฉพาะวันนี้" หรือ "ทั้งชุด"
- วันหยุดวันที่ตายตัว (ปีใหม่ สงกรานต์ ฯลฯ) ซ้ำทุกปีอัตโนมัติ วันหยุดตามจันทรคติ (มาฆบูชา วิสาขบูชา อาสาฬหบูชา เข้าพรรษา) Admin กรอกปีละครั้ง

### 4.4 นิสัย (Habit) / Check-in / Streak

Habit ต่างจากงานที่ทำซ้ำตรงที่มี streak สถิติ และไม่มีวันสิ้นสุด มี 2 ประเภท: แบบทำ/ไม่ทำ (เช่น นั่งสมาธิ) และแบบนับจำนวน มีเป้าต่อวันและหน่วย (เช่น ดื่มน้ำ 8 แก้ว)

| รหัส | ความต้องการ |
| --- | --- |
| FR-H1 | สร้าง habit: ชื่อ, รายละเอียด, ประเภท, เป้าและหน่วย (แบบนับ), วันที่ต้องทำ (ทุกวัน / เลือกวันในสัปดาห์), สี/ไอคอน, เวลาที่ตั้งใจทำ (ไม่บังคับ) และ goal ที่เชื่อม (ไม่บังคับ) |
| FR-H2 | แก้ไขและลบ habit (ลบแล้วประวัติหายด้วย ต้องยืนยันก่อน) |
| FR-H3 | Check-in วันนี้: แบบทำ/ไม่ทำกดครั้งเดียว แบบนับกด +1 หรือพิมพ์จำนวน |
| FR-H4 | ยกเลิกหรือแก้จำนวน check-in ของวันนี้ |
| FR-H5 | หน้ารวม habit แสดง streak ปัจจุบันและความคืบหน้าวันนี้ของแต่ละ habit |
| FR-H6 | หน้ารายละเอียด habit: streak ปัจจุบัน, streak สูงสุด, อัตราสำเร็จ 30 วัน, ยอดรวมรายเดือน และปฏิทินรายเดือนแยกวันที่ถึงเป้ากับวันที่ทำบางส่วน |
| FR-H7 | Check-in ประจำวันของแอป: เปิดแอปครั้งแรกของวันได้ XP |

#### กฎทางธุรกิจ

- check-in ได้เฉพาะวันนี้ วันที่ผ่านไปแล้วแก้ไขไม่ได้
- แบบนับ: ทำมากกว่า 0 แต่ไม่ถึงเป้า = streak ไม่ขาด จำนวนเข้ายอดรวม แต่ไม่นับเป็นวันที่ถึงเป้า / ถึงเป้า = streak ต่อและนับเป็นวันที่ถึงเป้า / 0 = streak ขาด
- streak นับเฉพาะวันที่กำหนด วันที่ไม่ได้กำหนดไม่ทำให้ streak ขาด
- พลาดวันที่กำหนด 1 วัน streak กลับเป็น 0
- ไม่มีการหยุดพักหรือ archive ไม่ทำคือขาด
- แก้เป้าหรือวันที่ต้องทำ มีผลตั้งแต่วันนี้ วันที่ผ่านมาใช้ค่าเดิม
- habit ใหม่เริ่มนับจากวันที่สร้าง

### 4.5 XP และ Level

| รหัส | ความต้องการ |
| --- | --- |
| FR-X1 | ให้ XP อัตโนมัติตามตารางค่า XP (ภาคผนวก ก) |
| FR-X2 | แสดง Level และแถบ XP เช่น Lv 3 · 45 / 121 XP |
| FR-X3 | หน้าประวัติ XP แสดงที่มา เวลา และจำนวน |
| FR-X4 | ประวัติงานและ habit แสดง XP ที่ได้ของแต่ละรายการ |
| FR-X5 | เลเวลอัปแสดง popup แสดงความยินดี |

#### กฎทางธุรกิจ

- กิจกรรมเดียวกันได้ XP ครั้งเดียว ทำซ้ำไม่ได้เพิ่ม
- ย้อนงานจาก DONE ระบบเตือนก่อนว่า XP จะหาย เมื่อยืนยันจึงหัก XP
- XP จากงาน (ส่วนตัวและกลุ่ม) ได้ไม่เกินวันละ 200 XP เกินแล้วยังทำงานได้แต่ไม่ได้ XP และมีข้อความแจ้ง
- งาน CANCELLED / SKIPPED ไม่ได้ XP
- เลเวลอัปแล้วแถบ XP เริ่มใหม่ XP ที่เกินทดไป Level ถัดไป
- Level ไม่ลดลง ย้อนแล้ว XP ในแถบลดได้ต่ำสุด 0
- XP ถูกบันทึกทันทีพร้อมกับการทำกิจกรรมนั้น
- Admin แก้ XP ของผู้ใช้ไม่ได้ และไม่มี API สาธารณะสำหรับให้ XP เอง
- ค่า XP ทั้งหมดกำหนดไว้ที่เดียวใน Backend
- สิ่งที่ได้จากการเลเวลอัป ยังไม่กำหนด (รอตัดสินใจ)

### 4.6 เป้าหมาย (Goal)

เป้าหมายมีแบบเดียวคือแบบตัวเลขพร้อมหน่วย เช่น วิ่ง 100 km

| รหัส | ความต้องการ |
| --- | --- |
| FR-G1 | สร้าง goal: ชื่อ, เป้า (ตัวเลข) และหน่วย, วันเริ่มและ deadline (ไม่บังคับ), habit ที่เชื่อม (ไม่บังคับ) |
| FR-G2 | แก้ไขและลบ goal (ต้องยืนยันก่อน) การลบคือวิธียกเลิก goal |
| FR-G3 | บันทึกความคืบหน้าเอง เช่น +5 km |
| FR-G4 | เชื่อม habit กับ goal ได้จากฟอร์ม goal หรือฟอร์ม habit จำนวนที่ check-in จะบวกเข้า goal อัตโนมัติ |
| FR-G5 | หน้ารวมและหน้ารายละเอียด goal: ความคืบหน้า (เช่น 72 / 100 km · 72%), วันที่เหลือ และประวัติการบันทึก |
| FR-G6 | เมื่อถึงเป้า แสดง popup ให้เลือก "เพิ่มเป้า" หรือ "จบ goal" |
| FR-G7 | เลย deadline แล้ว (FAILED) ขยายวันได้ |

#### ขั้นตอนการใช้งาน

**สถานะของ goal (เปลี่ยนอัตโนมัติ)**

1. สร้างใหม่ = NOT_STARTED
2. เริ่มบันทึกความคืบหน้า = IN_PROGRESS
3. ถึงเป้าและกด "จบ" = COMPLETED
4. เลย deadline โดยยังไม่ถึงเป้า = FAILED ขยายวันแล้วกลับเป็น IN_PROGRESS

#### กฎทางธุรกิจ

- ไม่มี milestone ไม่ผูกกับงาน และไม่มีสถานะ CANCELLED
- goal กับ habit เชื่อมแบบ 1 ต่อ 1 นับตามปริมาณ เช่น goal ดื่มน้ำ 140 แก้ว check-in วันนี้ 5 แก้ว goal +5
- เชื่อมได้เฉพาะ habit แบบนับจำนวน และนับเฉพาะ check-in หลังเชื่อม
- ได้ +25 XP ครั้งเดียวเมื่อ COMPLETED และต้องจบหลังสร้างอย่างน้อย 1 วัน
- กด "เพิ่มเป้า" ยังไม่ได้ XP
- ลบ goal แล้ว habit ที่เชื่อมยังอยู่ แค่ไม่ได้เชื่อมแล้ว

- XP จากงานกลุ่มนับรวมในเพดาน 200 XP ต่อวัน
- แก้ไข/ลบงานกลุ่มได้โดยผู้สร้าง ผู้รับผิดชอบ และเจ้าของกลุ่ม
- อันดับรีเซ็ตเที่ยงคืนเวลาไทย ถ้าจำนวนเท่ากัน คนที่ทำครบก่อนอยู่อันดับสูงกว่า
- ออก / ถูกนำออก / กลุ่มถูกลบ งานกลุ่มนั้นหายจากหน้าของผู้ใช้ XP ที่ได้ไปแล้วไม่หาย
- ถ้าผู้ที่ออกรับผิดชอบงานร่วมกับคนอื่น งานยังอยู่ในกลุ่มโดยไม่มีชื่อเขา

- งาน habit goal และ XP ของผู้ใช้แต่ละรายการเป็นของผู้ใช้เพียงคนเดียว
- ผู้ใช้ให้ XP ตนเองผ่าน API สาธารณะไม่ได้
- กิจกรรมเดียวกันต้องไม่ได้ XP ซ้ำ
- งานที่ทำซ้ำซึ่งถูกข้าม ไม่ถือว่าเสร็จ
- streak ของ habit ขึ้นกับวันที่กำหนด
- ดวงรายวันต้องคงเดิมสำหรับผู้ใช้และวันเดียวกัน
- ผู้ใช้เข้าถึงข้อมูลส่วนตัวของผู้อื่นไม่ได้ ยกเว้นงานกลุ่มในกลุ่มที่ตนเป็นสมาชิก
- ลบข้อมูลแล้วต้องไม่เหลือการอ้างอิงที่เสีย

## 6. ความต้องการที่ไม่ใช่เชิงฟังก์ชัน

### 6.1 ความปลอดภัย

- ทุก endpoint ตรวจสอบ token และความเป็นเจ้าของข้อมูลที่ Backend
- Endpoint ของ Admin ตรวจสอบ role ที่ Backend เสมอ การซ่อนเมนูที่ Frontend เป็นแค่ UX
- รหัสผ่านเก็บเป็น hash (bcrypt/argon2) และไม่บันทึกลง log

### 6.2 วันและเวลา

- เก็บเวลาเป็น timestamptz และแสดงผลตาม timezone ของผู้ใช้
- ขอบเขตของ "วัน" (check-in, ดวง, streak, เตือน) คำนวณตาม timezone ของผู้ใช้ ยกเว้นอันดับกลุ่มที่ใช้เวลาไทย

### 6.3 ภาษา

- UI รองรับอังกฤษและไทย ค่าเริ่มต้นอังกฤษ ผู้ใช้สลับได้และระบบจำค่าไว้

### 6.4 การแสดงผล

- Responsive Web รองรับทั้ง desktop และมือถือ
- ทุกหน้ารองรับสถานะ กำลังโหลด / ไม่มีข้อมูล / ผิดพลาด / สำเร็จ
- การลบทุกครั้งต้องยืนยันก่อน

### ก.3 สถานะและค่าที่กำหนด

| หัวข้อ | ค่า |
| --- | --- |
| Task | TODO, IN_PROGRESS, DONE, CANCELLED, SKIPPED |
| Goal | NOT_STARTED, IN_PROGRESS, COMPLETED, FAILED |
| Role | USER, ADMIN |
| Priority | LOW, MEDIUM, HIGH |
| การทำซ้ำ (V1) | NONE, DAILY, WEEKLY |

## ภาคผนวก ข: รายการที่จะทำภายหลัง
